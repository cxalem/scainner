# 3D scene patterns (VehicleScene and anything three.js)

Lessons from the C4 model saga (2026-08-19/20). These were expensive to
learn; do not relearn them.

1. Faceted "camo" shading on low-poly meshes means flat normals, not
   corruption. Check vertex sharing first (index count == vertex count
   means fully unwelded). Fix at load with toCreasedNormals (about 45
   degrees keeps hard edges).
2. High-metalness materials render as their environment. A chrome object
   in a black-void environment renders black. The studio env scene has a
   gray background for exactly this reason; keep roughness at or above
   about 0.2 for chrome-like parts.
3. KHR_materials_transmission with no interior geometry renders as a black
   void. Use alpha blend or opaque dark glass with clearcoat instead.
   Translucent glass only works when there is something behind it to see.
4. Verify at multiple rotation angles. The scene auto-rotates slowly
   (about 39s per turn when connected). One angle proves nothing; several
   screenshots spaced 4-10s apart do.
5. Tune materials at runtime on cloned materials, not by patching GLB
   JSON. Runtime tuning is reversible, diffable, and testable.
6. When a generated asset misbehaves, audit its data before changing code:
   per-primitive triangle counts, UV presence, material assignments. The
   segmentation repair script (scripts/repair-c4-glb.mjs) is the model for
   data-driven fixes with ground truth.
7. Emblem scene constraints: camera [4.4, 2.6, 4.4] fov 30 aimed at
   origin; content must fit roughly y 0 to 1.0 and width about 2.2 to
   avoid cropping in the h-64 card. Emblems center near EMBLEM_Y (0.32).
   Reuse EMBLEM_CHROME material and the spin-speed pattern keyed to
   SceneStatus.
8. New brand emblems, in order of preference: a real STL of the mark (see
   rule 10) beats a traced SVG (SVGLoader + ExtrudeGeometry) beats a
   hand-authored THREE.Shape outline (like the Citroen chevrons) — each is
   a step closer to the actual mark instead of an approximation of it.
   Keep per-emblem triangle counts modest; this renders in a small card,
   not a hero view.
9. Anything loaded with useLoader is cached and shared. Clone before
   mutating (geometry and materials), dispose clones on unmount.
10. STL emblems (public/emblems/stl, wired in emblems.tsx's StlEmblem):
    three things every one of these needs, learned getting the first 12
    brands right in one pass.
    - toCreasedNormals is not optional, it is unconditional. STL is a facet
      soup by format (three unshared vertices per triangle, no exceptions),
      so skipping this on a file that happens to load fine today is a bug
      waiting for the next re-export to trigger it. See rule 1.
    - Do not assume one fixed up-axis per batch. These files came from at
      least two export pipelines (mixed ASCII/binary STL headers in the
      same folder) with no shared convention. Detect the depth axis from
      the bounding box instead (whichever axis is thinnest, on a flat
      medallion that's the extrusion depth) and rotate that to Z — this
      is a proper rotation, so it cannot mirror the artwork, only choose
      which face points which way.
    - Front/back facing still needs a human look. Auto-orientation gets
      the mark flat and right-side up; it cannot know which of the two
      faces should point at the camera's side of the spin, and a wrong
      guess reads as a mirrored letterform for half of every rotation.
      Check each brand in the running app, not just that it loaded.
